# 장중 급등락 모니터

장중에 짧은 주기로 스냅샷을 찍고, **평소 변동성 대비 이례적인** 움직임만 골라
원인을 웹 검색으로 확인한 뒤 텔레그램으로 보냅니다.
**미국 주식·한국 주식 모두 한국투자증권 KIS OpenAPI** 하나로 받습니다.

```
monitor.py                     본체 (--market us | kr | fut)
kis.py                         KIS OpenAPI 래퍼 (국내주식·해외주식·해외선물)
paper.py                       모의투자 주문 + 텔레그램 승인 버튼
backfill.py                    알림 이후 수익률 채우기 + 성과 집계
requirements.txt               requests + anthropic 뿐
.github/workflows/intraday-us.yml
.github/workflows/intraday-kr.yml
.github/workflows/signal-review.yml
.github/workflows/intraday-fut.yml   ← 스케줄 없음 (수동 실행 전용)
```

> **해외선물 직접 모니터링은 쓰지 않기로 했습니다.** KIS 해외선물 시세는 거래소별
> 유료 신청이 전제라 이 용도에 비용이 맞지 않습니다. 원자재·금리·달러는 **미국 ETF
> 로 우회 추적**하며 그 ETF 들은 이미 미국 관심종목에 들어 있습니다. 대체 매핑은
> 아래 "해외선물 대신 ETF" 를 보세요.

## 시세가 실시간인가

KIS 공식 문서에 명시돼 있습니다.

> 지연시세 지연시간 : **미국 — 실시간무료(0분지연)** / 홍콩, 베트남, 중국, 일본 — 15분지연

즉 미국 종목은 별도 신청이나 추가 비용 없이 실시간으로 받습니다. 아시아 시세만
15분 지연이고 이 모니터는 아시아를 보지 않습니다. 같은 문서에 **"미국의 경우 장중
당일 시가는 상이할 수 있으며 익일 정정 표시됩니다"** 라는 단서가 있어, 시가가 아니라
**전일종가(base)** 를 기준으로만 등락률을 계산합니다.

## 해외선물 대신 ETF

처음에는 해외선물도 같이 보게 만들었지만, 시세 비용 때문에 접었습니다. 기록을
남겨 둡니다 — 나중에 같은 고민을 하실 때 다시 계산하지 않으셔도 되도록.

**해외선물은 거래소별로 시세를 따로 신청해야 합니다.** 계좌만 있으면 되는 줄 알기
쉬운데, 신청 안 된 거래소를 조회하면 REST 현재가조차
`EGW00550 CME SUB거래소 신청 계좌가 아닙니다` 로 막힙니다.

HTS `[7936] 해외선물옵션 실시간 시세신청` 의 **API(유료)** 기준 월 이용료입니다
(2026년 9월).

| 거래소 | 월 이용료 | 주요 품목 |
|---|---|---|
| ICE US / Financial / Commodity | 시세료 $0 | DX(달러인덱스), BRN(브렌트), SB·KC·CC(설탕·커피·코코아) |
| CME | $228.8 | ES, NQ, 6E, 6J |
| CME NYMEX | $228.8 | CL, NG, RB, HO |
| CME CBOT | $228.8 | ZC, ZS, ZW, ZN, ZB |
| CME COMEX | $228.8 | GC, SI, HG |

CME 계열 네 곳이면 **월 $915 (약 127만원)** 입니다. ICE 는 시세료가 0원이지만
**그 앞단의 HTS+MTS 이용 등급 자체가 유료**라 (ICE US $152.46 / Financial $142.07 /
Commodity $166.32, 각 6개월) 결국 무료 경로가 아닙니다.

그래서 **선물은 포기하고 미국 ETF 로 우회**합니다. 해외주식 시세는 추가 비용이
없으므로 이쪽은 월 0원입니다. 아래 ETF 는 전부 미국 관심종목에 이미 들어 있어
따로 설정하실 것이 없습니다.

| 보고 싶던 선물 | 대신 보는 ETF |
|---|---|
| ES / NQ / RTY (지수) | SPY, QQQ, IWM, DIA |
| ZN / ZB (금리) | TLT, IEF |
| 6E / 6J / DX (달러) | UUP |
| GC / SI (금·은) | GLD, SLV |
| HG (구리) | CPER |
| CL / NG (원유·가스) | USO, UNG, XLE |

ETF 는 선물보다 반 박자 느리고 거래시간도 정규장으로 짧습니다. 야간 선물 급변은
다음 날 개장 갭으로 보입니다. 그 대신 **미국 주식과 같은 판정 로직·같은 원인 분석**
을 그대로 받습니다.

`intraday-fut.yml` 은 **자동 실행 일정을 뺐습니다.** 파일과 코드(`--market fut`)는
그대로 두었으니, 나중에 시세를 신청하시면 그 파일의 `schedule:` 블록만 되살리면
됩니다. 지금은 Actions 탭에서 수동으로 눌렀을 때만 돕니다.

## 감시 주기

깨어 계신 한국장은 촘촘하게, 주무시는 미국장은 개장 직후에만 촘촘하게 봅니다.

| | 구간 | 주기 | 후보 |
|---|---|---|---|
| 한국 | 09:00~15:35 KST 내내 | 60초 | 등락률 순위 상하위 + 추적분 + 관심종목 |
| 미국 | 09:30~12:25 ET | 60초 | 3개 거래소 등락률·거래량급증 순위 + 관심종목 |
| 미국 | 12:26~16:00 ET | **1시간** | 같음 (순위 깊이 2배) |

미국장은 **개장 후 3시간까지 60초, 그 뒤 마감까지 1시간에 한 번**입니다.
09:30~12:25 ET 는 서머타임 기준 22:30~01:25 KST 로, 아직 깨어 계실 수 있는
구간이라 촘촘하게 둡니다. 그 뒤는 주무시는 시간이라 촘촘히 볼 이유가 없지만,
놓치면 아침에 영문을 모르게 되므로 완전히 비우지는 않았습니다. 서머타임 양쪽
모두 13:00 / 14:00 / 15:00 / 16:00 ET 네 번 돕니다.

전 종목을 훑지 않습니다. KIS 등락률 순위와 거래량급증 순위가 이미 "지금 크게
움직이는 것"을 골라 주므로, 거기에 **항상 보는 관심종목**과 **한 번이라도 순위에
들었던 종목(추적분)** 을 더합니다. 대형주는 8% 급락해도 등락률 순위 상위에는 못
드는 날이 많아, 관심종목이 그 구멍을 메웁니다.

**중요 — cron 으로는 1분 간격이 불가능합니다.** GitHub Actions 의 `schedule` 은
최소 간격이 5분이고, 그마저 5~15분씩 밀립니다. 그래서 크론을 자주 도는 대신
**한 번 깨어나 60초 루프를 도는 장시간 잡** 구조로 만들었습니다. 잡 하나의
최대 수명이 6시간이라 한국은 오전/오후 두 잡으로 나눕니다.

## 탐지 기준

단순 등락률만 쓰면 원래 변동성이 큰 종목이 매일 걸립니다. 두 경로 중
**하나라도** 걸리면 알립니다.

**(A) 일중 누적** — 아침부터 지금까지의 움직임

| 조건 | 기본값 | 이유 |
|---|---|---|
| 절대 등락률 | ±4% 이상 | 통계적으로 이례적이어도 폭이 작으면 볼 필요 없음 |
| z (일간 변동성 대비) | 3.0σ 이상 | 그 종목 기준으로 이례적인가 |
| 거래량 배수 | 같은 시각 평소의 1.8배 | 가격만 튀고 거래가 없으면 호가 공백일 뿐 |

**(B) 순간 급변** — 최근 5분 사이의 움직임. **1분 폴링의 존재 이유입니다.**

| 조건 | 기본값 | 이유 |
|---|---|---|
| 5분 변동폭 | ±2% 이상 | |
| z (해당 구간 환산 변동성 대비) | 3.5σ 이상 | 일간 σ 를 √(측정구간/390분) 으로 환산 |
| 그 5분 구간의 거래량 | 평소 같은 길이의 1.8배 | 누적거래량 차분으로 계산 |

(A) 만 보면 **갭상승 후 종일 횡보하는 종목이 계속 걸립니다.** (B) 는 지금 막
벌어지는 것만 잡아냅니다. 알림에 `순간급변` / `급변+누적` / `누적` 으로 어느
경로에 걸렸는지 표시되고, 순간급변이 먼저 정렬됩니다.

폴링이 밀려 측정 구간이 5분이 아니라 8분이 되면 **임계치도 그 길이로 다시
환산**합니다. 그러지 않으면 구간이 넓어질수록 임계가 저절로 헐거워집니다.
체결 이력은 `state/` 에 저장해 실행 간에 넘기므로, 1시간 단발 스캔에서도
직전 스캔 대비 순간 변동을 잴 수 있습니다.

일간 변동성과 평균거래량은 **오늘 자 봉을 뺀** 최근 20영업일로 구합니다.
오늘 봉을 넣으면 지금 잡으려는 급등이 제 자신의 σ 를 키워 z 를 눌러버립니다.

여기에 같은 종목 **120분 재알림 금지**, 1회 스캔 4건 / **시간당 8건 / 하루 한국 30건·
미국 20건** 상한이 걸립니다. 1분 루프에서는 상한이 없으면 변동성 큰 날 API 비용이 그대로
늘어납니다.

원인 분석은 일일 귀인과 같은 원칙입니다. 날짜가 확인되는 사실만 쓰고, 확인되지
않으면 **"확인된 촉발 사건 없음"** 으로 둡니다. 장중에는 원인이 아직 보도되지 않은
경우가 흔하므로 이것이 정상적인 결과입니다.

## 모의투자 반자동 체결

알림에 **매수 승인 버튼**이 붙습니다. 누르면 KIS 모의계좌에 주문이 나가고,
청산은 규칙대로 자동으로 됩니다. 실제 돈은 움직이지 않습니다.

### 왜 완전자동이 아닌가

금융투자회사 표준내부통제기준과 협회 컴플라이언스 매뉴얼(자산운용편) 기준으로,
운용인력의 개인계좌 매매에는 **준법감시인 사전승인**(유효기간 2영업일),
**매수일로부터 5영업일 이상 보유의무**, **일간 매수주문 3회 수준의 횟수 제한**이
걸립니다. 실제로 적용되는 것은 회사 자체 PA dealing 정책이라 이것보다 더
빡빡할 수 있습니다.

알고리즘이 아직 정하지도 않은 주문은 사전승인을 받을 방법이 없습니다.
**사람이 버튼을 눌러야 주문이 나가는 구조**만이 그 체계와 개념적으로 양립합니다.
그래서 이건 자동매매가 아니라 반자동이고, 지금은 모의계좌에서만 돕니다.

부수 효과가 하나 더 있습니다 — 승인한 표본의 수익률에서 전체 알림 평균을 빼면
**재량이 알파를 더하는지 빼는지**가 숫자로 나옵니다. 집계의 마지막 줄이 그것입니다.

### 시세는 실전 키, 주문만 모의 키

모의투자 환경은 해외주식 시세·순위 API 가 제한되고 REST 호출 한도도 낮습니다.
지금 스캔을 모의 키로 옮기면 미국 쪽이 통째로 막힙니다. 그래서 KIS 클라이언트를
**둘** 띄웁니다.

| | 키 | 도메인 | 하는 일 |
|---|---|---|---|
| 조회 | 실전 | `openapi...:9443` | 시세·순위·일봉 (지금 그대로) |
| 주문 | 모의 | `openapivts...:29443` | 매수·매도·잔고 |

시크릿 세 개를 추가하세요 — `KIS_PAPER_APP_KEY`, `KIS_PAPER_APP_SECRET`,
`KIS_PAPER_ACCOUNT`(계좌 10자리). 모의투자 앱키는 **실전 키와 별개로 발급**받아야
하고, 실전 키를 모의 도메인에 넣으면 토큰부터 거부됩니다.

주문은 **신 TR**(`VTTC0012U` 매수 / `VTTC0011U` 매도)을 씁니다. KIS 스펙에
"구TR은 사전고지 없이 막힐 수 있다"고 명시돼 있어, 구 TR 로 짜 두면 어느 날
조용히 주문이 안 나갑니다.

### 매매 규칙

| | 기본값 | 왜 |
|---|---|---|
| 대상 | 한국장만 | 미국 알림은 자는 시간이라 승인이 불가능합니다. 로깅은 양쪽 다 합니다 |
| 주문금액 | 건당 1,000만원 고정 | 검증 단계에서는 변수를 줄입니다 — 수익률 차이가 신호 때문인지 사이징 때문인지 섞이지 않게 |
| 승인 유효시간 | 15분 | 지나면 만료 안내만 갑니다. 그때 가격과 벌어지면 다른 거래가 됩니다 |
| 익절 | 진입가 +5%, **D+1부터** | 당일 익절은 일봉 시뮬레이션이 잡지 못해 비교가 불가능해집니다. 손절은 당일에도 겁니다 |
| 시간청산 | T+5 영업일 | 가설이 맞으면 며칠 안에 확인됩니다. 안 되면 나갑니다 |
| 손절 | 진입가 −1.5×일간σ | 종목마다 다른 변동성에 맞춰 잡습니다 |
| 동시 보유 | 5종목 | |
| 상한가·하한가 | 승인해도 주문 안 함 | 반대 호가가 없어 실전에서는 체결이 안 됩니다. 모의에서만 체결되면 데이터가 오염됩니다 |
| 거래비용 | 왕복 0.55% 차감 | 모의투자는 슬리피지 없이 체결됩니다. 빼 줘야 실전에 가깝습니다 |

청산이 자동인 이유는 단순합니다. **진입에 재량이 들어가고 청산에도 재량이
들어가면, 결과가 좋든 나쁘든 무엇 때문인지 가릴 수가 없습니다.**

셋 중 **손절을 먼저 봅니다.** 한 스캔에서 손절선과 익절선이 동시에 맞았다면
장중에 위아래로 크게 흔들렸다는 뜻인데, 그때 나쁜 쪽을 가정해야 성과가
부풀지 않습니다. 시뮬레이션도 같은 규칙을 씁니다.

승인은 한 박자 늦습니다 — 알림, 버튼, 다음 스캔. 실제 진입은 급변 발생 후
3~5분입니다. 일 단위 호라이즌이면 문제없지만 **장중 스캘핑은 이 구조로
불가능합니다.**

### 포지션의 진실 원천은 잔고 API

GitHub Actions 캐시는 날아갈 수 있습니다. 장부(`state/paper_book.json`)는
'왜 샀는지·언제 나갈지' 처럼 잔고에 없는 것만 들고, **수량과 보유 여부는 매
회차 KIS 잔고 API 와 대조**합니다. 잔고에 없으면 장부에서 지웁니다.

조회 **실패**와 **빈 잔고**는 반드시 구분합니다. 실패를 빈 잔고로 읽으면 보유
중인 포지션을 전부 지워 버리고, 그러면 손절선을 넘겨도 아무도 팔지 않습니다.

### 첫 설정

1. KIS 에서 모의투자 계좌를 개설하고 **모의투자 전용 앱키**를 발급받습니다.
2. 저장소 Settings → Secrets 에 위 세 개를 넣습니다.
3. Actions → 한국 워크플로 → Run workflow → **"모의투자 연결만 확인"** 체크 →
   실행. 토큰·계좌·잔고까지만 확인하고 **주문은 내지 않습니다.**
4. 정상이면 다음 장중부터 알림에 버튼이 붙습니다.

버튼을 끄고 싶으면 워크플로의 `PAPER_TRADING` 을 `0` 으로 두세요. 알림과 로깅은
그대로 돌고 버튼만 사라집니다.

**반자동이 깨져도 알림은 나갑니다.** `paper.py` 가 없거나, 모의 키가 틀렸거나,
초기화가 실패해도 로그에 한 줄 남기고 알림·로깅은 그대로 돕니다. 급변을 알려
주는 것이 이 시스템의 본래 일이고 반자동은 부가 기능이라, 부가 기능 때문에
본체가 멈추지 않도록 세 군데를 막아 두었습니다.

## 신호에 엣지가 있는지 — 전수 로깅

이 시스템이 뽑는 신호에 엣지가 있는지는 **아직 아무도 모릅니다.** 장중 스냅샷
기반이라 과거 데이터가 존재하지 않아 백테스트도 불가능합니다. 그래서 지금부터
쌓습니다.

`state/signals.jsonl` 에 **승인 여부와 무관하게 모든 알림**이 남습니다. 가격,
등락률, z, σ, 탐지 경로, 귀인 원문까지. 반자동으로 체결된 것만 보면 그것은 고른
표본이라, "이 신호에 엣지가 있나" 에는 영영 답할 수 없습니다.

`signal-review.yml` 이 매일 07:00 UTC(16:00 KST)에 돌면서 `backfill.py` 로
T+1·T+5 수익률을 채우고 집계를 텔레그램으로 보냅니다. 한국장이 끝난 뒤이고
미국장 루프와도 겹치지 않는 유일한 구간입니다.

### 익절 수준은 데이터가 고릅니다

"몇 %에서 익절할 것인가" 는 지금 답할 수 없습니다. 그래서 하나를 고르는 대신,
**같은 표본에 여러 익절 수준을 동시에 적용**해 결과를 나란히 냅니다. 손절선은
실제 운용과 같은 −1.5σ 로 고정하고 익절만 바꿉니다.

```
익절 수준 비교 (n=90, 손절 −1.5σ 고정)
  `익절없음` 평균 +0.48%  승률 49%  (익절  0% · 손절 37%)  보유 3.8일
  `익절 +3%` 평균 −0.20%  승률 58%  (익절 47% · 손절 33%)  보유 2.5일
  `익절 +5%` 평균 +0.11%  승률 52%  (익절 29% · 손절 37%)  보유 3.2일
  `익절 +8%` 평균 +0.53%  승률 51%  (익절 13% · 손절 37%)  보유 3.6일
  → 현재 표본 최선: +8% 익절 (평균 +0.53%)
```

승률과 평균수익률이 반대로 움직이는 게 보이실 겁니다. 익절을 낮게 잡으면
자주 이기지만 크게 못 먹고, 평균은 오히려 나빠질 수 있습니다. 보유일수도
같이 냅니다 — 같은 수익률이면 빨리 도는 쪽이 자본 회전에서 낫습니다.

시뮬레이션은 **일봉 고가·저가**로 경로를 재현하는데, 두 가지를 보수적으로
가정합니다. 알림 당일(D0)은 **종가만** 봅니다 — 진입이 장중이라 그날 고가에는
진입 전 구간이 섞여 있고, 그걸 쓰면 사지도 않은 가격에 익절한 것으로
기록됩니다. 그리고 같은 봉에서 익절선과 손절선을 모두 건드리면 순서를 알 수
없으므로 **손절이 먼저 닿았다고 봅니다.** 둘 다 성과를 깎는 방향입니다.

`TP_GRID` 로 시험할 수준을 바꿀 수 있습니다 (기본 `0,3,5,8,12`). 0 은 익절 없이
시간청산·손절만 쓰는 기준선이라 빼지 마세요 — 비교 대상이 없어집니다.

집계는 이렇게도 갈라서 봅니다.

- 방향별 — 급등 알림(추종)과 급락 알림(반등 베팅)
- 탐지 경로별 — 순간급변 / 누적
- **원인 유무별** — "확인된 촉발 사건 없음" 과 그 외. 원인이 특정되지 않은 급변은
  수급 충격일 가능성이 높고, 그렇다면 되돌림이 나와야 합니다. 가설의 1차 검증입니다
- 승인 표본 − 전체 평균 = 재량의 기여

**판단은 100건 넘은 뒤에 하세요.** 3개월이면 대략 그 정도 쌓입니다.

원본 jsonl 은 공개 저장소에 커밋하지 않습니다 — 관심종목이 그대로 드러납니다.
필요하면 workflow_dispatch 의 "원본 첨부" 를 켜서 텔레그램 비공개 대화로 받으세요.

### 해외선물 코드는 남아 있습니다 (지금은 안 돎)

아래는 `--market fut` 를 되살리실 때를 위한 기록입니다. 현재 워크플로는 자동

주식과 달리 "오늘 많이 오른 선물" 을 뽑아 주는 API 가 없어서, **볼 품목을 정해 두고
근월물을 매일 자동으로 찾습니다.** 종목코드는 `ROOT + 월물코드 + 2자리연도`
(예: 금 2026년 12월물 = `GCZ26`) 이고, 품목마다 상장월이 달라 월물표를 들고 있기보다
가까운 월부터 실제로 조회해 보고 **잔존일수가 `FUT_ROLL_DAYS`(기본 4일) 이상인
첫 월물**을 씁니다. 하루 한 번만 찾고 `state/fut_symbols.json` 에 캐시합니다.

쿨다운과 체결 이력은 월물이 아니라 **품목 단위**(`GC`, `ES` …)로 겁니다. 그리고
**롤오버로 월물이 바뀌면 그 품목의 이력을 버립니다** — 월물이 달라지면 가격 수준이
점프하는데 이력을 이어 두면 롤을 '순간 급변'으로 오인합니다.

기본 품목은 **시세료 0원인 ICE 것만** 골랐습니다 — `DX,BRN,WBS,MEM,SB,KC,CC`
(달러인덱스·브렌트·WTI·MSCI신흥국·설탕·커피·코코아). `FUT_ROOTS` 로 바꿀 수 있고,
CME 를 신청하셨다면 `ES,NQ,ZN` 처럼 넣으면 그대로 동작합니다. 알림에는 한글
품목명으로 표시됩니다.

무료 ICE 품목은 변동성 폭이 넓습니다 — 달러인덱스가 일간 0.35%, 코코아가 3%.
그래서 선물 워크플로의 최소 등락률 하한을 **0.8%** (순간 0.4%)로 낮춰,
고정 하한이 아니라 **z(3σ) 조건이 실제 판정을 하도록** 해 두었습니다.
2% 하한이면 달러인덱스는 3σ 급변이 와도 영영 안 걸립니다.

선물은 세션이 23시간이라 **순간급변 임계를 √(구간/1380분)으로 환산**합니다.
주식의 390분을 그대로 쓰면 임계가 1.9배 헐거워져 오탐이 쏟아집니다.
일중 누적 거래량비는 18:00 ET 에 하루가 바뀌는 구조 탓에 경과 비율 계산이 꼬이기
쉬워 **쓰지 않습니다**(근월물은 유동성이 충분해 '호가 공백' 걱정이 적습니다).
순간 구간 거래량비는 세션 길이만 있으면 되므로 그대로 작동합니다.

## 2. GitHub Actions 설정

### 저장소 만들기
새 저장소를 **공개(Public)** 로 만들고 이 폴더의 파일을 그대로 올립니다
(`.github/workflows/` 경로 유지). 공개로 하는 이유는 아래 무료 한도 항목에 있습니다.

### 시크릿 등록
저장소 → **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 필수 | 비고 |
|---|---|---|
| `KIS_APP_KEY` | ✅ | 미국·한국 공용 |
| `KIS_APP_SECRET` | ✅ | 〃 |
| `ANTHROPIC_API_KEY` | ✅ | [platform.claude.com/settings/keys](https://platform.claude.com/settings/keys) |
| `ANTHROPIC_WORKSPACE_ID` | 조건부 | 조직 범위 키일 때만 (`wrkspc_...`) |
| `TELEGRAM_TOKEN` | ✅ | 기존 봇 토큰 재사용 가능 |
| `TELEGRAM_CHAT_ID` | ✅ | 〃 |
| `KR_WATCHLIST` | 선택 | `005930,000660,035720` 형식 |
| `US_WATCHLIST` | 선택 | `NVDA,TSM,SPY` 형식. 비우면 기본 목록 사용 |
| `FUT_ROOTS` | 선택 | `ES,NQ,GC,CL` 형식. 비우면 기본 13품목 |

**관심종목도 Variables 가 아니라 Secrets 에 넣으세요.** 공개 저장소에서는
Variables 가 로그에 평문으로 남지만 Secrets 는 `***` 로 마스킹됩니다.

### 공개 저장소에서 무엇이 가려지나

워크플로에 `QUIET_LOG: "1"` 이 들어 있습니다. 이걸 켜면 알림 **건수만** 로그에
남고 종목코드·등락률은 남기지 않습니다. 정리하면 이렇습니다.

| 항목 | 공개 로그에 | 
|---|---|
| API 키·토큰·텔레그램 토큰 | `***` 마스킹 |
| 관심종목 목록 (Secrets 로 넣었을 때) | `***` 마스킹 |
| 어떤 종목이 걸렸는지 | `QUIET_LOG=1` 이면 안 남음 |
| 알림 본문·원인 분석 | 애초에 로그로 안 나가고 텔레그램으로만 감 |
| 스캔한 종목 수, 알림 건수, 오류 | 남음 (민감하지 않음) |

즉 공개 저장소라도 **무엇을 보는지·무엇이 걸렸는지는 드러나지 않습니다.**
다만 저장소에 이 코드가 공개된다는 점, 그리고 하루 몇 건이 걸렸는지 같은
빈도 정보는 보인다는 점은 남습니다.

### cron 이해하기

`on.schedule.cron` 은 **UTC 기준**이고 필드는 `분 시 일 월 요일` 입니다.

```yaml
- cron: "30 13 * * 1-5"   # UTC 13:30, 월~금  (= 서머타임 중 09:30 ET)
```

서머타임 때문에 미국장 09:30 ET 는 UTC 로 13:30(EDT) 또는 14:30(EST) 입니다.
cron 은 서머타임을 모르므로 **두 시각 모두 걸어두고**, `--skip-if-after 10:15`
으로 "이미 다른 잡이 맡은 구간이면 즉시 종료" 시킵니다. 선물은 08:30 ET 에도 장이 열려 있어 `--skip-if-before 09:30` 가드가 하나 더 붙습니다. 해당 없는 쪽은 몇 초 만에
끝납니다. 같은 이유로 2단계(1시간 주기)는 UTC 16~21시를 전부 덮고
`--skip-if-before 12:26` 으로 1단계와 겹치는 구간을 잘라냅니다.

알아두실 점 셋입니다. GitHub cron 은 **정시 보장이 없어** 5~15분 지연됩니다
(루프 안에서는 영향 없고, 잡이 뜨는 시각만 밀립니다). **60일간 커밋이 없으면
스케줄이 자동 비활성화**되니 가끔 커밋하거나 Actions 탭에서 다시 켜 주세요.
그리고 **잡 하나는 6시간에 강제 종료**되므로 `--max-minutes` 로 그 전에 스스로
빠져나오게 해 두었습니다.

### 무료 한도

| | 분/일 | 분/월(21영업일) |
|---|---|---|
| 한국 (오전 180 + 오후 215) | 약 400 | 약 8,400 |
| 미국 (루프 175 + 1시간 단발 4회) | 약 187 | 약 3,900 |
| **합계** | | **약 12,300** |

해외선물 워크플로를 되살리면 여기에 월 12,000분이 더 붙습니다.

비공개 저장소 무료 한도는 월 2,000분, 초과분은 Linux 기준 분당 $0.006 이라
그대로 돌리면 월 $62 정도가 붙습니다. **공개 저장소는 Actions 분이 무제한**이라
비용이 0입니다. 상시 켜 둘 장비(본인 PC, 소형 VPS)가 있다면 셀프호스티드 러너를
붙이는 방법도 있고, 그 경우 비공개 저장소에서도 Actions 분을 쓰지 않습니다.

공개 저장소라 분이 무제한이므로, 원하시면 미국도 마감까지 60초 루프로 늘릴 수
있습니다 (`intraday-us.yml` 의 `--loop-until` 을 15:55 로, 2단계 잡 삭제).
지금은 "자는 시간에는 1시간이면 충분하다"는 전제로 나눠 두었습니다.

### 첫 실행 확인 — 주말에도 됩니다

Actions 탭에서 워크플로를 고르고 **Run workflow** → **"장 시간을 무시하고 즉시
1회 스캔" 체크** → 실행하세요. 장이 닫힌 주말에도 돌고, 루프가 아니라 단발이라
2~3분이면 끝납니다. 이 한 번으로 아래가 전부 확인됩니다.

- KIS 토큰 발급 (`KIS 토큰 신규 발급` 로그)
- 시세·순위 API 권한 (`KIS 오류 [tr_id] ...` 가 뜨면 권한 문제)
- 텔레그램 전송 (기준 충족 종목이 있으면 메시지가 옵니다)

체크를 안 하고 실행하면 평소처럼 장 시간을 보고 `장 시간 아님 → 종료` 로 끝납니다.
로컬에서 돌려 보실 수도 있습니다.

```bash
pip install -r requirements.txt
export KIS_APP_KEY=... KIS_APP_SECRET=...
export ANTHROPIC_API_KEY=... TELEGRAM_TOKEN=... TELEGRAM_CHAT_ID=...

python monitor.py --market us --force                   # 단발
python monitor.py --market us --force --universe full   # 순위 2배 깊게
python monitor.py --market kr --force \
       --loop-until 15:35 --interval 60                 # 루프 (KST 기준)
python monitor.py --market kr --paper-probe             # 모의투자 연결만 확인
python backfill.py                                      # 수익률 채우고 집계 출력
python backfill.py --send --attach                      # 집계+원본을 텔레그램으로
# 아래 둘은 해외선물 시세를 신청하신 경우에만 의미가 있습니다
python monitor.py --market fut --force                  # 해외선물 단발
python monitor.py --market fut --force \
       --loop-until 16:00 --interval 60                 # 선물 루프 (ET 기준)
```

`--force` 는 장 시간 검사를 건너뜁니다. 텔레그램 토큰이 없으면 전송 대신
화면에 그대로 출력하므로, 문구만 확인하실 때 편합니다. 처음 돌릴 때는
`QUIET_LOG` 를 켜지 말고 어떤 종목이 걸리는지 눈으로 확인해 보세요.

## 3. 임계 조정

워크플로의 `env` 에서 바꿉니다. 처음에는 기본값보다 **높게** 잡아 알림을 적게
받아보고, 놓치는 게 있다 싶을 때 낮추는 편이 낫습니다.

| 변수 | 기본 | 설명 |
|---|---|---|
| `Z_THRESHOLD` | 3.0 | 일중 누적 경로. 낮출수록 알림 급증 |
| `MIN_ABS_PCT` | 4.0 | 최소 등락률(%) |
| `VOL_RATIO_MIN` | 1.8 | 거래량 동반 조건 |
| `BURST_MIN` | 5 / 60 | 순간 변동 측정 구간(분). **스캔 간격에 맞추세요** — 60초 루프는 5, 1시간 단발은 60 |
| `BURST_Z` | 3.5 | 순간 경로 임계. **알림이 너무 많으면 여기부터 올리세요** |
| `BURST_MIN_PCT` | 2.0 | 순간 변동 최소 폭(%) |
| `MAX_ALERTS` | 4 | 1회 스캔당 상한 |
| `MAX_PER_HOUR` | 8 | 시간당 상한 |
| `MAX_PER_DAY` | 30 / 20 | 하루 상한. 한국 / 미국 (**비용을 묶는 핵심 손잡이**) |
| `COOLDOWN_MIN` | 120 | 같은 종목 재알림 금지(분) |
| `RANK_N` | 20 | 순위에서 가져올 종목 수 (방향·거래소별) |
| `SURGE_N` | 10 | 거래량급증 순위에서 가져올 수 (미국) |
| `TRACK_MAX` | 40 | 순위에서 빠진 뒤에도 계속 볼 종목 수 |
| `VOL_RANG` | 3 | 해외 순위 거래량 조건 (3=1만주 이상) |
| `WORKERS` | 4 | 개별 현재가 동시 조회 수 |
| `FUT_ROLL_DAYS` | 4 | 잔존일수가 이보다 적으면 다음 월물로 |
| `QUIET_LOG` | 0 | 1이면 로그에 종목명을 남기지 않음 |
| `PAPER_TRADING` | 0 | 1이면 알림에 모의투자 승인 버튼을 붙임 (한국장만) |
| `PAPER_ORDER_KRW` | 10,000,000 | 승인 1건당 주문금액(원) |
| `APPROVE_TTL_MIN` | 15 | 승인 버튼 유효시간(분) |
| `HOLD_DAYS` | 5 | 시간청산 — T+N 영업일 |
| `STOP_SD` | 1.5 | 손절 — 진입가 −N×일간σ |
| `TAKE_PROFIT_PCT` | 5.0 | 익절 — 진입가 +N%. 0 이면 끔 |
| `TP_GRID` | 0,3,5,8,12 | 집계에서 시뮬레이션할 익절 수준(%) |
| `MAX_POSITIONS` | 5 | 동시 보유 종목 수 |
| `ROUND_TRIP_PCT` | 0.55 / 0.25 | 왕복 거래비용(%) 가정. 한국 / 미국 |

로그에 `주의: 스캔 1회에 NN초` 가 뜨면 한 바퀴가 간격보다 오래 걸린다는 뜻입니다.
관심종목이나 `TRACK_MAX` 를 줄이거나 `WORKERS` 를 6~8로 올리세요.

## 비용

KIS 시세는 무료이고 GitHub Actions 도 공개 저장소면 0원이라, 드는 것은 Anthropic
API 뿐입니다. Sonnet 5 가 입력 $2 / 출력 $10 per MTok, 서버측 웹 검색이 1,000회당
$10 입니다.

알림은 한 묶음(여러 종목을 한 번에 조사)으로 나갑니다. 4종목 묶음 기준으로 검색
8회가 $0.08, 출력이 $0.02, 그리고 검색 결과가 대화에 누적되며 쌓이는 입력이
$0.05~0.20 입니다 — **묶음당 대략 $0.15~0.30**.

폭이 넓은 것은 누적 입력 토큰이 검색 횟수와 결과 길이에 따라 크게 달라지기
때문입니다. 아직 실제 청구로 확인한 값이 아니니, 며칠 돌려 보신 뒤
[Anthropic 콘솔의 Usage](https://console.anthropic.com/settings/usage) 에서
실제 금액을 보고 아래 추정을 조정하세요.

| | 하루 상한 | 최대 묶음/일 | 월 상한(21영업일) |
|---|---|---|---|
| 한국 | 30건 | 8 | $25~50 |
| 미국 | 20건 | 5 | $16~32 |
| **합계** | | **13** | **$41~82** |

이것은 **상한을 매일 다 쓰는 최악의 경우**이고, 보통은 하루 4~6묶음이라 월
$20~40 수준으로 보입니다. 여기에 기존 일일 귀인이 월 $12 내외로 따로 붙습니다.

비용을 더 줄이려면 순서대로 이렇습니다. `MAX_PER_DAY` 는 절대 상한이라 원하는
금액에 정확히 맞출 수 있습니다(묶음당 단가를 곱하시면 됩니다).
`SEARCH_PER_NAME` 을 2→1 로 낮추면 검색 비용과 누적 입력 토큰이 같이 줄어 체감이
큽니다. `ATTRIB_MODEL` 을 Haiku 로 바꾸면 토큰 단가가 절반이지만 원인 분석 품질은
떨어집니다.

## 알려진 한계

- **컨테이너에서 KIS 에 접속할 수 없어 실호출 검증은 못 했습니다.** 엔드포인트와
  tr_id·파라미터·응답 필드는 KIS 공식 저장소 예제에서 그대로 가져왔고, 파싱·판정
  로직은 가짜 응답으로 458개 항목을 검증했습니다. 실제 응답이 다르면 로그에
  `KIS 오류 [tr_id] msg_cd: ...` 가 한 번 찍히도록 해 두었으니 그 줄을 보내주세요.
- **미국 후보는 순위 기반**이라, 순위에 들지 않는 종목은 관심종목에 없으면 놓칩니다.
  기본 관심종목에 대형주·섹터 ETF·반도체를 넣어 두었고 `US_WATCHLIST` 로 교체할
  수 있습니다.
- 순위에 갓 진입한 종목은 직전 시세 이력이 없어 **첫 5분간은 순간급변 판정을 못 하고**
  일중 누적 경로로만 걸립니다. 한 번 순위에 든 종목은 빠진 뒤에도 `TRACK_MAX` 개까지
  계속 추적해 이력을 잇습니다.
- **원자재·금리·달러는 ETF 대리라 정규장(09:30~16:00 ET)에만 보입니다.** 야간에
  선물이 크게 움직여도 알림은 다음 날 개장 갭으로 옵니다. 선물 시세를 신청하시면
  `intraday-fut.yml` 의 `schedule:` 을 되살려 24시간 가까이 볼 수 있습니다.
- 선물 옵션은 다루지 않습니다. KIS 에 API 는 있습니다(`opt_price` 등).
- 시가 갭은 순간급변으로 잡히지 않습니다. 개장 전 이력이 없기 때문이며, 갭은
  일중 누적 경로가 담당합니다.
- 해외 종목의 거래소(NAS/NYS/AMS)는 코드만으로 알 수 없어 처음 한 번 탐색해
  `state/us_excd.json` 에 적어 둡니다. 상장 이전이 있으면 그 파일을 지우세요.
- **비용 추정은 실제 청구로 확인한 값이 아닙니다.** 며칠 돌려 보신 뒤 콘솔에서
  실제 금액을 확인하세요.
- **모의투자 체결가는 실전보다 낙관적입니다.** 슬리피지 없이 호가에 바로 체결되는
  구조라, 급변 종목에서 실제로 밀리는 0.3~0.5% 가 반영되지 않습니다. 집계에
  비용 차감값을 같이 내지만 그것도 가정입니다. 모의 수익률은 **상한선**으로
  보세요.
- **−1.5σ 손절은 5영업일 보유의무와 충돌합니다.** 일간 σ 2% 종목이면 손절선이
  −3% 인데, 보유의무의 예외는 평가손실 10% 이상입니다. 모의계좌에서는 문제가
  없지만, 이 규칙을 그대로 실계좌로 옮기면 보유의무 위반이 됩니다. 실전 전환을
  검토하실 때 반드시 준법감시인과 먼저 상의하세요 — 그때는 손절을 빼거나
  10% 로 늘리는 쪽이 됩니다.
- **KIS 모의투자 주문 API 는 실호출로 검증하지 못했습니다.** 컨테이너에서
  KIS 에 접속이 안 됩니다. tr_id 와 요청 형식은 공식 스펙 기준이고 응답 파싱은
  가짜 응답으로 검증했습니다. `--paper-probe` 가 첫 확인용입니다.
- 모의투자 계좌는 **REST 호출 한도가 실전보다 낮습니다.** 그래서 시세는 실전 키로
  받고 모의 도메인에는 주문과 잔고조회만 보냅니다. 회차당 몇 건뿐이라 여유가
  있지만, 보유 종목을 크게 늘리면 이 부분부터 걸립니다.
